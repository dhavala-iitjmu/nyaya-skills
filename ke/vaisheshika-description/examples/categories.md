# Worked category analysis and adversarial contrasts

## A red pot is moved from a table

Supplied facts: a particular red pot is touching a table at t1 and is moved to a
shelf at t2. Nothing says its color changes. The task is an engineering adaptation
of the descriptive method, not proof of all classical metaphysical commitments.

| Item | Category analysis, mapping and limit |
| --- | --- |
| This pot | Material bearer/dravya example; keep it distinct from a record of the pot. Its persistence across the stated move is assumed by the supplied narrative, not inferred from a matching label. |
| This pot's particular redness | Guṇa in a bearer; distinguish the particular quality from a measured color code and the universal of which the quality is an instance. Do not invent a measurement. |
| Its stated movement | Karma as motion; distinguish movement from static color. A database update recording the move is a separate representational event. |
| The repeatable kind potness | A candidate classical universal/sāmānya in the historical lens; an application's `Pot` class is an explicit modeling convention, not proof of that commitment. |
| Pot/table contact | Separable conjunction/saṃyoga; relocation changes this contact while the pot persists. It is not samavāya merely because an edge connects them. |
| Redness/bearer; a whole and its constitutive material parts | Developed inherence examples. The narrative does not specify this pot's parts; describe the relation type without inventing part instances. A list of members or foreign keys alone would not establish it. |
| Inventory ID `pot-17` | Operational identifier. Do not call it literal viśeṣa; leave ultimate individuation unassigned for this practical task. |

At t2, a claim “this pot is absent from the table” has a specified counterpositive,
locus and time, but requires evidence that relocation actually occurred and the
negative claim is justified. The temporal statement alone is not a classification
as timeless atyantābhāva. A missing database record supplies weaker evidence.

## Measured model quality

Input: model artifact M evaluated on dataset D with split S, seed R and metric
procedure P has MAE 0.49. Expected result distinguishes M, its record, the
evaluation event, the reported value and the configuration to which that value
applies. Treating M as an operational bearer and evaluation quality as a contextual
property is an engineering analogy. It does not prove that model artifacts are
classical dravyas or that MAE is an intrinsic quality across all contexts.

## Contrasts the skill must preserve

- A pot's moving and being red are not the same category. A training job changing
  status may use a process analogy but is not thereby classical karma.
- Two equal UUID strings identify the same record only under a specified
  namespace/uniqueness rule. They do not prove world-object identity or constitute
  ultimate particularity.
- `partOf`, ownership, containment and spatial contact must not all become
  samavāya. State the actual relation and any analogy's limits.
- An arbitrary model cluster is an operational grouping; it is not established
  sāmānya solely by receiving a label.
- An empty incomplete index proves no world-level absence. Specify the relevant
  counterpositive, locus, time, completeness/detectability and limits.
- Historical reconstruction and a practical schema are different tasks. An
  efficient schema does not settle a historical interpretation, and a missing
  classical mapping is preferable to a fabricated one.
